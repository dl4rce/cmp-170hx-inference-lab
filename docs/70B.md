# 70B / 72B class on one 170HX

The buy question for this card is not 27B (a 3090 can do that). It is whether **70B-class W4A16 fits and is usable**.

We ran **Qwen2.5-72B-Instruct-AWQ** (public, ungated, ~39 GB). Llama-3.1/3.3-70B AWQ is the same size class; we did not download a gated Meta checkpoint.

## What other people run

| Suite | What it answers | Used here? |
|---|---|---|
| **vLLM `bench serve --dataset-name random`** (ISL/OSL × concurrency) | Serving speed, TTFT, TPOT. Default in vLLM docs and most 70B GPU write-ups | **Yes** — [scripts/bench_vllm_random.sh](../scripts/bench_vllm_random.sh) |
| ShareGPT (`--dataset-name sharegpt`) | Chat-shaped mix of lengths | No. Needs a large JSON dump; hides prefill vs decode |
| NVIDIA SPEED-Bench / GuideLLM (1k/1k, 10 min × many concurrences) | Datacenter SLO curves | No. This SKU has 4 slots and 250 W; a 10-minute 650-concurrency sweep is the wrong tool |
| llama.cpp `llama-bench` (pp / tg) | GGUF prefill vs generate | No. This lab is vLLM AWQ, which is what you actually serve |
| MMLU / HumanEval / MT-Bench | Quality | No. Quality of Qwen2.5-72B is already public; the card question is speed and VRAM |
| Needle-in-haystack / RULER | Long context | Yes, a 30k exact buried-key (native window is **32K**, not 128K) |

Best default if you re-run: the random ISL/OSL matrix, plus one single-stream code decode, plus load wall and `nvidia-smi` power. That is what buyers compare.

## What the 170HX actually did

Load: **38.77 GiB in 20.28 s** (weights 9.38 s) on Gen2 ×16. KV **123,744** tokens, **3.78×** at 32 768. vLLM refused `max-model-len 131072` (`max_position_embeddings=32768`). Do not set `VLLM_ALLOW_LONG_MAX_MODEL_LEN`.

Single-stream code decode (400 tok, n=3): **25.77 tok/s**, warm TTFT 53 ms, **~249 W**.

4 agents, same code prompt: **100.4 tok/s aggregate**, 25.44 per stream.

Exact buried key at 29,987 tokens: pass.

### vLLM random ISL/OSL (prefix cache on)

Output tok/s is generated tokens / wall. TPOT stays ~39–41 ms (**~25 tok/s/stream**) until prefill dominates.

| ISL → OSL | conc | n | output tok/s | total tok/s | median TTFT | median TPOT |
|---|---:|---:|---:|---:|---:|---:|
| 128 → 128 | 1 | 8 | 24.77 | 55 | 210 ms | 39.0 ms |
| 512 → 128 | 1 | 8 | 23.19 | 121 | 513 ms | 39.4 ms |
| 2048 → 128 | 1 | 8 | 18.36 | 316 | 1.93 s | 39.7 ms |
| 8192 → 128 | 1 | 4 | 9.66 | 630 | 8.09 s | 40.7 ms |
| 128 → 256 | 1 | 8 | 25.39 | 41 | 56 ms* | 39.3 ms |
| 512 → 128 | 4 | 16 | **79.37** | 415 | 809 ms | 40.2 ms |

\*TTFT after other 128-ISL cells; prefix cache.

Read this as: **72B decode is ~25 tok/s and already at TDP**. Batching to 4 streams gives ~80 tok/s aggregate, not 4×25, because prefill and the 250 W cap share the card. An 8k prompt waits **8 s** before the first token. A 24 GB 3090 cannot load this checkpoint at all.

Reproduce:

```bash
# serve Qwen2.5-72B-Instruct-AWQ at max-model-len 32768, no MTP
BASE_URL=http://127.0.0.1:8000 MODEL=qwen72-awq \
  TOKENIZER=/path/to/Qwen2.5-72B-Instruct-AWQ \
  bash scripts/bench_vllm_random.sh
python3 scripts/bench_72b.py --base-url http://127.0.0.1:8000 --model qwen72-awq
```
